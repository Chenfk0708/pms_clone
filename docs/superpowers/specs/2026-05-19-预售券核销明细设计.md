# 预售券核销明细设计

## 背景

目标页面为 `/statistics/preSaleCouponMall`，页面名称为“预售券核销明细”。

当前仓库中的实现 [src/pages/PresaleCouponMallReportPage.tsx](/C:/Users/Administrator/Desktop/work/xxxxx/pms_clone/src/pages/PresaleCouponMallReportPage.tsx) 仍是静态页面：

- 组件内直接持有门店、日期、下拉、说明和表格空态常量。
- 没有独立服务层、provider 切换、统一响应包或字段适配层。
- 没有 success / empty / error / loading 闭环。
- 现有测试 [tests/pre-sale-coupon-mall-report.spec.ts](/C:/Users/Administrator/Desktop/work/xxxxx/pms_clone/tests/pre-sale-coupon-mall-report.spec.ts) 只覆盖旧静态行为。

## 核心问题

真实页面当前主列表为空，无法直接用真实数据构造“业务可用态”。但 prompt 明确要求：

- 本地页面默认必须表现为正常业务可用状态。
- mock 数据必须来自接口契约建模，而不是为 UI 临时拼字段。
- 后续接后端时只能复用同一契约、adapter 与服务层。

因此不能继续沿用静态空表，也不能只做目标页的空态镜像。

## 设计目标

将该页面改造成“服务层驱动的业务页”，满足以下条件：

- 路由、菜单、页面壳层维持现有项目结构，不改全局导航方案。
- 页面只消费适配后的业务模型。
- 所有筛选项、按钮、弹层、空态、失败态、详情入口均有真实反馈。
- 默认展示 success 业务态，同时支持 empty / error 验证。
- 产出可交给后端继续实现的接口文档草案。

## 方案

### 1. 服务层

新增 `src/services/preSaleCouponMallReport.ts`，职责如下：

- 定义 provider：`mock | api`
- 定义 mock state：`success | empty | error`
- 定义查询参数 `PreSaleCouponMallQuery`
- 定义统一响应包：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "mock-baobiao--yushouquan-shuju--yushouquan-hexiao-mingxi-001",
  "timestamp": "2026-05-18T10:00:00+08:00"
}
```

- 定义原始接口模型：
  - 门店选项
  - 渠道选项
  - 预售券类型选项
  - 列表项
  - 分页
- 定义适配后的业务模型：
  - 筛选项 options
  - 列表 rows
  - 汇总卡片 metrics
  - 说明 rows
  - 快捷反馈 traceIds / updatedAt
- 暴露：
  - `defaultPreSaleCouponMallQuery`
  - `resolvePreSaleCouponMallProvider`
  - `fetchPreSaleCouponMallDashboard`
  - `createPreSaleCouponMallExportTask`
- 在 `api` provider 下显式抛错，不做静默 fallback。

### 2. 页面层

保留 [src/pages/PresaleCouponMallReportPage.tsx](/C:/Users/Administrator/Desktop/work/xxxxx/pms_clone/src/pages/PresaleCouponMallReportPage.tsx) 作为页面入口，但整体改为服务驱动：

- 初始化 query，并从 URL query 读取 `mockState`
- `useEffect` 拉取 dashboard
- 筛选区使用服务层 options 渲染
- 默认 success 态渲染：
  - 门店切换
  - 日期范围
  - 渠道下拉
  - 预售券类型下拉
  - 商品搜索
  - 指标卡片
  - 明细表格
  - 行内详情按钮
- 支持：
  - 查询
  - 重置
  - 刷新
  - 导出
  - 说明弹层
  - 行详情弹层
  - empty
  - error + retry
  - loading 禁用态

页面内不再保留 mock 常量数组。

### 3. 数据建模

由于真实页返回空列表，本地 success mock 采用“契约先行 + 字段语义保守推断”的方式：

- 以真实表头字段为准建模，不扩展与页面无关的业务字段。
- 生成一组稳定、可读、可复现的示例数据：
  - 商品名称
  - 成交券数
  - 交易金额
  - 成交率
  - 核销券数
  - 核销金额
  - 核销率
  - 退款券数
  - 退款金额
  - 退款率
- 详情弹层展示：
  - 商品名称
  - 预售券类型
  - 关联渠道
  - 适用门店
  - 最近更新时间
  - 备注说明

### 4. 反馈与状态

- `loading`：查询、刷新、导出期间按钮禁用，页面显示状态提示。
- `success`：显示卡片、表格、弹层、通知提示。
- `empty`：页面结构保留，表格为空态，卡片归零。
- `error`：显示错误提示与重试按钮。

不出现“mock 数据”“后端未接入”等开发态文案。

### 5. 验证

测试重写为以服务驱动页面为核心，覆盖：

- 默认 success 页面渲染
- empty 页面渲染

- 查询 / 重置 / 刷新 / 导出反馈
- 日期面板、下拉和说明弹层
- 详情弹层
- 路由与菜单高亮
- 隐藏诊断节点输出请求参数与 provider/state

## 风险与边界

- 真实页说明弹层存在全局页面其他弹层干扰，本轮不把说明弹层文案取证作为阻塞项；本地采用与字段语义一致的说明文案，并在接口文档里标注“说明文案待产品确认”。
- 真实页当前查询未稳定观察到带 `keyword` 的新请求，不据此捏造额外请求字段；本地 query 仍保留 `keyword`，用于 mock 过滤和后续接口对接。
- 不改全局 `AppShell`、不抽象通用报表框架，避免与并行任务冲突。
