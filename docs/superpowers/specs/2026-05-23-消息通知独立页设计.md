# 消息通知独立页复刻设计

## 背景

- 用户入口是顶栏消息图标，当前点击后跳转到本地路由 `/setting/notification`。
- 目标页面已取证成功，真实业务页为 `https://minsubao.localhome.cn/setting/wechatPushSetting`。
- 当前本地已有 `NotificationSettingPage`，但视觉语义仍然偏“设置子页”，与用户要的“消息图标进入一个独立页面”不一致。

## 目标

将顶栏消息图标承接的页面替换为独立复刻页，使用户点击消息图标后进入的页面在结构、视觉和交互上接近目标页，不再表现成原有设置页。

## 非目标

- 不新增新的业务路由体系。
- 不重写现有通知服务契约。
- 不扩展目标页之外的通知能力。
- 不为了兼容旧页再保留双套视觉实现。

## 已确认约束

- 保留消息图标点击入口，不改用户操作路径。
- 现有页面直接替换，不保留“当前设置页版本”作为并行页面。
- 页面是独立页面，但仍挂在现有应用壳层中。
- 不增加静默 fallback、假成功提示或吞错逻辑。

## 推荐方案

保留路由 `/setting/notification` 作为消息图标入口页，同时将页面实现改造成独立业务页，并从“设置页语义”中抽离。`/setting/wechatPushSetting` 继续复用同一页面实现，方便目标页映射与脚本抓取。

原因：

- 用户点击链路不变，改动面最小。
- 现有 `NotificationSettingPage` 已有数据流、开关、刷新、关注和弹层逻辑，可复用。
- 只需要替换布局语义和壳层归类，不需要为独立页再造一套路由和服务。

## 页面设计

### 1. 入口与路由

- 顶栏消息图标继续通过 `handleTopbarTool('notice')` 跳转到 `/setting/notification`。
- `App.tsx` 中 `/setting/notification` 与 `/setting/wechatPushSetting` 继续指向 `NotificationSettingPage`。

### 2. 页面定位

- 该页面在视觉上视为独立业务页，不再视为“设置中心 > 通知设置”的普通子页。
- 页面进入后不应强调设置导航上下文，不应让用户感觉只是设置页换皮。

### 3. 布局结构

- 顶部保留页面主内容区，不额外显示旧式设置页标题条。
- 首屏核心结构：
  - 公众号关注区
  - 轻量操作按钮区
  - 通知设置表格区
  - 公众号列表弹层
- 页面主体采用目标页的轻量白底业务面板，减少当前较强的渐变和卡片装饰感。

### 4. 视觉方向

- 优先贴近目标页的业务后台风格，而不是当前偏“设计强化”的卡片页。
- 颜色回归中性：白底、浅灰边框、弱阴影、深灰文本、蓝色链接/开关。
- 降低圆角、渐变、背景氛围和悬浮感，使页面更像系统真实后台。
- 表格头、行高、边框、按钮文案位置按目标页收紧。

### 5. 信息结构

- 顶部文案保留“扫码关注公众号【路客云】，快速通过微信推送订单、房态”这一核心引导。
- 操作按钮保留：
  - `我已关注？`
  - `刷新一下`
- 表格按目标页信息结构保留三列逻辑：
  - 通知项说明
  - `PC\APP推送`
  - `公众号推送`
- 通知项至少覆盖已取证到的四类：
  - 订单通知
  - 门店预警
  - 门店动态
  - IM消息通知

### 6. 交互

- `我已关注？`：触发当前已有关注确认逻辑，并刷新反馈。
- `刷新一下`：触发当前已有刷新逻辑。
- 列头总开关与行级开关：继续复用现有切换逻辑。
- “查看接受微信通知公众号”：继续打开当前已有弹层。
- 弹层关闭：支持关闭按钮和遮罩点击关闭。
- `loading`、`error`、`empty` 状态继续显式暴露，不做静默处理。

## 壳层与导航调整

### 1. 页面归类

- `AppShell.tsx` 中需要把 `/setting/notification` 从普通系统设置路径语义中分离。
- 该页不应展示信息维护侧边导航，不应强调“设置菜单选中状态”作为主要感知。

### 2. 内容容器

- 为该页增加独立页面判定，使用更贴近目标页的内容宽度、留白和背景。
- 避免继承当前设置页相关容器样式造成的布局噪音。

## 实施范围

- `src/components/AppShell.tsx`
  - 调整 `/setting/notification` 的壳层归类与导航表现。
- `src/pages/NotificationSettingPage.tsx`
  - 重构页面结构表达，保留核心交互与服务契约。
- `src/pages/NotificationSettingPage.css`
  - 替换为贴近目标页的独立业务页样式。
- 视需要补充或更新通知页相关测试。

## 验证标准

- 点击顶栏消息图标后，进入的是独立通知页，而不是旧的设置观感页面。
- 页面可稳定落到 `/setting/notification`。
- 页面可见以下核心内容：
  - `我已关注？`
  - `刷新一下`
  - `查看接受微信通知公众号`
  - `PC\APP推送`
  - `订单通知`
  - `门店预警`
  - `门店动态`
  - `IM消息通知`
- 行级与列级开关可交互。
- 弹层可打开、关闭。
- `loading`、`error`、`empty` 状态仍可渲染。

## 风险与处理

- 当前本地抓取脚本 `--clone` 落点异常，说明路由承接或 hash/preview 行为可能有干扰。
  - 处理：实现后优先补做本地点击链路验证，而不是只验证直达路由。
- 若完全去掉设置语义，可能影响现有壳层复用。
  - 处理：只对 `/setting/notification` 做特例，不影响其他设置页。
- 现有服务模型若与目标页字段不完全一致，可能出现视觉结构和数据结构轻微偏差。
  - 处理：优先保持结构一致，数据字段继续映射现有 view model。

## 实现顺序

1. 修正壳层判定，确保消息图标进入独立页语义。
2. 改造 `NotificationSettingPage` 的结构与文案层级。
3. 替换样式，压到目标页风格。
4. 验证点击入口、直达路由、开关、弹层和状态页。
