# 订单录入抽屉前端复刻设计
## 背景

- 当前本地住宿订单页位于 [src/pages/OrdersPage.tsx](C:/Users/Administrator/Desktop/work/xxxxx/pms_clone/src/pages/OrdersPage.tsx)。
- 现状是 `录入订单` 按钮仅通过 `handleBlockedAction('录入订单')` 输出占位反馈，没有真实右侧抽屉。
- 目标页为 `https://minsubao.localhome.cn/order/house-order/list`，已完成登录态取证。
- 用户当前阶段只要求先完成前端页面与交互复刻，确认后再对齐后端接口和数据库。

## 目标

在本地住宿订单页中复刻目标站 `录入订单` 右侧抽屉，使其在结构、主要交互和视觉层级上与目标页保持一致，并支持以下三种订单类型切换：

- 全日房
- 钟点房
- 长租房

## 非目标

- 不接真实保存接口。
- 不改后端服务、数据库结构和接口契约。
- 不引入 mock 成功提示来伪装真实保存。
- 不实现依赖真实房态数据的复杂业务弹层，只保留前端占位交互入口。

## 已确认事实

### 1. 抽屉基础结构

- 目标页使用右侧抽屉，宽度约 `680px`。
- 顶部标题为 `录入订单`。
- 顶部右上角存在关闭按钮。
- 顶部订单类型切换为三段按钮：
  - `全日房`
  - `钟点房`
  - `长租房`

### 2. 全日房

- 分组顺序：
  - 基本信息
  - 房间/费用信息
  - 收款信息
  - 开票信息
  - 订单提醒
  - 订单标签
  - 订单备注
- 基本信息字段：
  - `默认为入住人信息` 复选框
  - `姓名` 必填
  - `手机号`
  - `订单来源`，默认 `自来客`
  - `渠道单号`
- 房间/费用信息：
  - 头部显示 `房费总计: ¥0 | 共0间房`
  - 右侧 `添加房间`
  - 当前默认空态下，房间列表未展开具体已选房卡片
  - 下方有 `佣金`、`押金`
- 收款信息：
  - `房费收款` 单选：`已收 / 未收 / 现场收`
  - `已收房费`
  - `收款方式`，默认 `平台代收`
  - `押金收款` 默认禁用
  - `已收押金` 默认禁用
  - `押金收款方式` 默认禁用，显示 `微信`
- 开票信息：
  - `开票方`
  - `开票金额`
- 底部：
  - `房费(减佣): ¥0.00`
  - `订单总收入：¥0.00`
  - 主按钮 `提交`

### 3. 钟点房

- 当前已取证到的默认空表单状态下，结构与全日房基本一致。
- 顶部仍为同一抽屉，切换后仅订单类型按钮状态变化。
- 底部主按钮同样为 `提交`。

### 4. 长租房

- 采用两步流程：
  - `1 填写订单信息`
  - `2 核对账单`
- 第一步包含以下分组：
  - 基本信息
  - 房间信息
  - 佣金
  - 租赁信息
  - 随房付费项目
- 基本信息字段：
  - `租客姓名` 必填
  - `手机号码` 必填
  - `紧急联系人姓名`
  - `紧急联系人电话`
  - `订单来源`，默认 `自来客`
- 房间信息区：
  - 表格列为 `房间/入离日期`、`每月租金`、`押金`、`人数`
  - 默认一行空态，房间列显示 `请选择`
  - 下方有 `佣金`
- 租赁信息区：
  - `合同时间`
  - `合同期限`
  - `缴费方式`：`月付 / 季付 / 半年付 / 一次性付清`
  - `缴费时间`：默认 `本月`、`1号`
  - `收租提醒`：默认 `开启`
- 随房付费项目：
  - `宽带费`
  - `公摊费`
  - `卫生费`
  - `物管费`
  - `停车费`
- 底部按钮：
  - `取消`
  - `保存后结束`
  - `保存后下一步`

## 实现设计

### 1. 接入点

- 将 `录入订单` 按钮从占位提示改为打开新的前端抽屉状态。
- 新增本地状态：
  - `isEntryDrawerOpen`
  - `entryOrderType`
  - 各订单类型的表单状态
  - 长租步骤状态

### 2. 组件组织

本轮不强制抽出新文件，优先在 `OrdersPage.tsx` 内新增以下局部组件：

- `OrderEntryDrawer`
- `FullDayOrderForm`
- `HourlyOrderForm`
- `LongRentalOrderForm`

这样可以在不扩大改动面的前提下，把抽屉逻辑与表格页主体隔离。

### 3. 抽屉行为

- 点击 `录入订单` 打开抽屉。
- 点击右上角关闭按钮或遮罩关闭抽屉。
- 切换订单类型时保留抽屉打开状态，只切换内部表单内容。
- 当前轮次不接真实保存，底部按钮点击仅更新本地反馈，不伪装成功。

### 4. 全日房与钟点房复刻策略

- 两者共用同一套基础表单骨架。
- 默认按照已取证空态复刻，不预设房间卡片数据。
- `添加房间` 先做为前端交互入口：
  - 可点击
  - 可在本地追加一条房间表单卡片或列表项
  - 不依赖后端房型数据
- 收款区域按取证结果呈现默认状态与禁用态。

### 5. 长租房复刻策略

- 第一轮先完整复刻第一步 `填写订单信息` 页面。
- 同时把顶部步骤条和底部三按钮流转搭好。
- `保存后下一步` 进入本地第二步视图 `核对账单`。
- 第二步在本轮至少需要具备：
  - 明确的步骤切换结果
  - 与目标页一致的抽屉结构和底部按钮语义
  - 可承接第一步已填写金额与费用的汇总展示

如果第二步线上明细仍需继续取证，允许本轮先用基于第一步字段推导的前端账单摘要来承接，但不能伪装成真实结算结果。

### 6. 状态模型

- 公共状态：
  - 当前抽屉开关
  - 当前订单类型
- 全日房/钟点房状态：
  - 基本信息字段
  - 房间列表
  - 收款方式与金额
  - 开票信息
  - 订单提醒
  - 订单标签
  - 订单备注
- 长租房状态：
  - 当前步骤
  - 租客基础信息
  - 房间信息行
  - 佣金
  - 租赁信息
  - 随房付费项目

## 交互边界

### 1. 本轮必须可交互

- 打开/关闭抽屉
- 三种订单类型切换
- 输入框、下拉、单选、复选框输入
- 长租步骤切换
- `添加房间` 点击响应

### 2. 本轮可占位但不能假装真实打通

- 房型选择数据源
- 房间库存校验
- 提交保存
- 真实账单核算

占位交互必须显式体现为前端本地行为，不应出现“已提交成功”之类误导反馈。

## 样式方向

- 优先贴近目标页的业务后台风格，不额外做设计强化。
- 关键视觉要点：
  - 抽屉固定宽度 `680px`
  - 白底、浅灰边线、细分组标题
  - 三段式订单类型切换
  - 紧凑表单栅格
  - 长租步骤条
  - 底部固定操作区

- 订单页点击 `录入订单` 后会打开右侧抽屉。
